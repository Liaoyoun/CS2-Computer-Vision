# YOLO MLOps 教學流程

一套教學用的範例：把 YOLO 物件偵測模型從程式碼檢查、訓練、紀錄，一路走到人工決定後上線。它獨立於任何學生的專案，目的是讓學生看懂完整流程後搬回自己的專案。

## Language

### 三條流程

**CI**:
程式碼被推送或提出合併請求時自動執行的檢查，不訓練模型。
_Avoid_: 測試流程、自動訓練

**訓練流程**:
由人手動啟動、帶參數執行的一次模型訓練，結束時產生一個模型版本。
_Avoid_: 自動訓練、CI 訓練

**部署流程**:
由人指定一個模型版本後啟動，把該版本變成正式環境中的偵測服務。
_Avoid_: 發布、上線流程、CD

### 模型

**模型版本**:
一次訓練流程註冊下來、帶有編號的模型，連同它的指標與參數。
_Avoid_: best、最佳模型、權重檔

**正式版**:
目前在正式環境提供服務的那一個模型版本；同一時間只有一個。
_Avoid_: best、最新版、champion（champion 是它在紀錄系統中的標記名稱，不是概念本身）

**部署關卡**:
人看過模型版本的指標後，決定是否啟動部署流程的那個決定點。訓練流程永遠不會自行跨過它。
_Avoid_: 自動升級、審核

**回滾**:
對先前的模型版本重新執行一次部署流程。
_Avoid_: 還原、降版

### 服務

**偵測服務**:
接收一張圖片、回傳邊界框與類別的服務，是部署流程唯一的產出。
_Avoid_: 推論伺服器、API、模型服務

**部署**:
在這裡專指讓某個模型版本成為正式環境中的偵測服務。把模型交給桌面應用程式使用不算部署。
_Avoid_: 發布、匯出

**正式環境**:
偵測服務實際對外提供服務的地方。
_Avoid_: 正式機、線上、prod

**GPU 執行機**:
被標記為具備顯示卡、訓練流程指定要在其上執行的機器。在這份教材中它是假設存在的。
_Avoid_: runner、訓練機、GPU 節點
